# 设计任务:把一个"惰性的树搜索"换成"裁决闭环的迭代循环"

> **给设计模型的话**:请为下面这个软件模块设计一套替代方案,直言不讳。背景完全自包含,不需要任何外部领域知识——这是一个纯粹的**候选生成 + 打分 + 搜索**架构问题。请给出可执行的设计,不要客气。
>
> **输出**:把完整设计写成一个 markdown 文件。方案里请明确:①控制流(伪代码级);②停止条件;③"往宽/往深"由什么信号驱动;④失败模式;⑤用什么**客观、不依赖模型自评、无法被刷**的指标,证明你的方案比"朴素 best-of-N"更好。

---

## 系统在做什么(领域中性)

一个流水线,让一个 LLM 生成若干**结构化文本候选**(每条含固定几个字段),再用**非模型的机械信号**给它们打分、排序,择优写进最终产物。目标是产出"高质量、可验证、有新意"的候选。

**已有的机械打分信号**(全部零模型判断):
1. **结构完整度**:候选的必填字段齐不齐(对成形的候选几乎恒为满分)。
2. **抗反驳存活度**:每生成一条候选,就让一个独立的"对抗 critic"尽力**击破**它,critic 输出一个分级裁决,被解析成 [0,1] 分。这是**真正在起作用的排序信号**。裁决分级与对应分:
   - `致命`(与证据矛盾,或空泛到不可检验)→ 0.00
   - `严重`(有重大缺陷)→ 0.35
   - `轻微`(小缺陷)→ 0.70
   - `无法反驳`(critic 用证据攻它、攻不动,站住了)→ 0.85
   - `证据不足`(critic 没有现成证据可攻——候选太新,但**有具体可证伪条件**)→ 0.68;若无具体证伪条件 → 0.45
   - `裁决未能解析`(critic 回复读不出分级)→ 0.50
3. **词汇新颖度**:仅作展示,不参与排序(实测对成形候选恒为满分,无判别力)。

**成本约束(硬):** 每轮运行只负担得起 **3–8 次额外 LLM 调用**,每次 30–90 秒。

---

## 现在的实现:一棵"惰性"的自适应分支树(AB-MCTS)

- 节点是候选;每个节点两个 Beta-Bernoulli 臂;用 Thompson 采样在「加宽(在当前节点生成一个新兄弟候选)」和「加深(精修某个已有子候选)」之间选。
- 每生成一条候选就 critic 裁决一次,反传更新臂的后验。

**为什么它是死重(实测 + 代码事实):**
1. **排序阶段根本不读树的后验**:最终 `finish()` 只按候选自己的分数排序取 top-K,那套 Thompson 后验/反传算完之后对"谁进产物"零影响。树唯一能影响产物的通道是"生成了哪些候选(宽/深)"。
2. **默认预算=3,每臂只有 0–2 个观测**,此时 Beta 后验与均匀分布几乎无差别——「加宽/加深」的选择接近抛硬币。
3. **实测:24 次扩展里,"加深"候选合法夺冠 0 次**。8 题里 7 题冠军是初稿种子。
4. **[树对照实测数据,待填]**:用"均匀随机选点"替换 Thompson,同题同种子跑 8 题 × 2 策略,深化夺冠率 = ___,冠军分数分布 Thompson vs 随机 = ___。

结论:整棵 bandit 机器在当前预算下是纯复杂度税。**要砍掉的**:Thompson 选点下降、O(n²) 的反传上溯、两个 Beta 臂、采样轨迹记录。**要保留的**:critic 裁决解析(这是唯一净增的信号)、"针对最强反驳的一遍精修"、诚实台账。

## 设计方向(要你评估/细化的种子):把树换成一个**裁决闭环的循环**

树最大的谎言是"假装用信号决定往哪走,实际没有"。一个循环能把这件事**真正做出来** ——用 critic 的裁决决定下一步往宽还是往深:

```
种子池 = 模型初稿产出的若干候选
对每条种子:critic 裁决 → 存活分,入池

循环(还有预算 且 未收敛):
    best = 池中存活分最高者
    若 best 已站住(无法反驳/轻微)且连续两轮无更优 → 收敛,停
    否则按 best 的裁决决定这一步:
        · best 是「严重/轻微」(critic 指明了具体可修的缺陷)
              → 【往深】针对这条最强反驳精修 best,产出改进版
        · best 是「致命 / 全池皆致命」
              → 【往宽】换一个与现有都不同的角度,生成新候选
        · best 是「证据不足」(新颖但没证据可攻)
              → [你来定:是接受它作为探索性前沿而停,还是再尝试一次多样化?]
    对新候选 critic 裁决 → 入池
    去重:与池中已有候选措辞高度重合的丢弃(防伪多样性)

排序取 top-K;台账如实记录每步往宽/往深、每条裁决、收敛原因
```

**这个循环相对树的优势**:①宽/深由裁决真正驱动(树是抛硬币);②天然实现"一遍针对最强反驳的精修";③停在"找到一条扛得住的"而非固定跑满预算;④没有名不副实的"自适应分支"。**这不是退化成 best-of-N,是升级成用信号闭环的迭代精修。**

## 要你回答的具体问题

1. 这个循环设计站得住吗?哪里会失败?**特别是**:"证据不足(新颖但无证据可攻)"这一档该怎么处理——它恰恰是本产品最想要的产出(够得着的新方向),但循环无法靠"再攻一次"改进它。接受即停?还是有别的机械办法提高对它的信心?
2. **收敛判据**该怎么定才不依赖模型自评?"连续两轮无更优"够吗?会不会在小预算(3 次)下几乎从不触发、退化成"固定跑满"?
3. **往深(精修)会不会有反效果**:让候选"扛住 critic 攻击"最省力的办法是把主张说软说空,而空泛候选天然拿高存活分。精修循环会不会系统性地把候选越修越空?有没有机械的挡板(不靠模型判断)?
4. **critic 与生成器同源**(同一个 LLM):一条在该模型先验里系统性成立、但实际错误的候选,critic 攻不动 → 判"无法反驳" → 循环反而加倍投入。循环会不会放大同源模型的共同盲区?能缓解吗?
5. 用什么**客观、不可刷、不依赖模型评判**的指标,证明这个循环**确实优于**"直接生成 N 个候选、各裁决一次、按存活分排序"(朴素 best-of-N)?如果证明不了,那就该直接上 best-of-N,别搞循环——请诚实判断。

## 一条要一并检验的"铁律"

**代理指标教训**:这个项目曾用一个粗糙的"量化论断计数"当质量门,结果它奖励凑数(把无关的背景数字也算进去)。⇒ **一个不做真活也能满足的代理指标,一定会被不做真活地满足;绝不在粗糙代理上设硬门。** 请检验:你设计的循环里,任何"往深/往宽/停止"的判据,会不会变成一个能被"把话说空"或"多生成几条"廉价满足的代理?
