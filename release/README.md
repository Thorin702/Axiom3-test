# 发布目录 · Release

**源码只有一套**(`axiom3-desktop/` + `crates/`),Tauri 跨平台编译。
本目录只放**各操作系统的发布产物与配置**,让每个正式版的 Windows / macOS 包各自独立、互不干扰。

- `windows/` — Windows 发布:`tauri.windows.conf.json` 覆盖配置、图标、打好的 `.msi`/`.exe`、发布说明、更新清单
- `macos/`   — macOS 发布:`tauri.macos.conf.json` 覆盖配置、图标、打好的 `.dmg`/`.app`、发布说明、更新清单

## 版本号规则
- 本地测试/增量更新:走**末位**,如 `1.1.0 → 1.1.1 → 1.1.2`
- 正式版发布:进**中间位**,如 `1.1.x → 1.2.0`
- 三处同步:`tauri.conf.json` + `src-tauri/Cargo.toml` + `package.json`

## 备份与回退机制(每个版本都必须做)
每次升版本、构建通过后,**按顺序**做三件事,保证任何版本都能回退:
1. **提交** —— 版本号 + 改动一起提交(提交前扫密钥)。
2. **打标签并推送** —— `git tag -a v<版本号> -m "..."` 然后 `git push origin <分支> v<版本号>`。
   标签 = **源码级回退点**:任何时候 `git checkout v1.0.29` 就能回到那个版本的源码。
3. **归档安装包(正式版)** —— 把打好的 `.msi`/`.dmg` 复制到 `release/<os>/<版本号>/`,
   这是**二进制级回退**:即使源码回退后构建环境变了,也有当时的成品可直接装。

回退操作:
- 回退源码:`git checkout v1.1.0`(或 `git reset --hard v1.1.0` 丢弃之后的改动)。
- 回退安装:直接装 `release/<os>/<旧版本>/` 里的旧安装包。
- ⚠️ 用户的**产出物/数据在 app_data 里、不在仓库**,回退 App 版本不会动到它们(deliverables.rs 磁盘库始终独立)。
